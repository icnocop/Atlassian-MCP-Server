# Changelog

All notable changes to this project are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow
[Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added

- Jira tools for issues, search, comments, links, attachments, projects, users, worklogs, filters, and agile boards.
- Confluence tools for pages, private drafts, section editing, search, spaces, comments, attachments, and labels.
- Markdown to Atlassian Document Format conversion for writing, and back to Markdown for reading.
- Toolsets, an allow list of tools, and a read-only mode.
- `atlassian_jira_add_attachment` and `atlassian_confluence_add_attachment` upload a local file by `filePath`, so that a file on disk no longer has to pass through the model as base64. Files in the folders that `ATLASSIAN_ATTACHMENT_FOLDERS` lists are uploaded directly; for any other file the server asks the user, through MCP elicitation, to allow it once, always allow its folder, or deny it.
- User mentions in Markdown for Jira and Confluence. `@[Display Name]` is resolved to an account ID with a user search, and `@[Display Name](accountid:ID)` gives the account ID directly; either becomes a mention that notifies the user. A name that matches no user, or more than one, fails the call before anything is written, listing the matching users and their account IDs. Mentions are read back as `@[Display Name](accountid:ID)`, so they survive a read, edit, and write, and a page that contains mentions can now be edited with Markdown.
- Embedded files in Jira rich text. `![name](attachment:ID)`, in a paragraph of its own, embeds a file already attached to the issue in a comment, description, environment, worklog comment, or multi-line custom field: images and videos inline, other files as file cards, as Jira's editor shows them. A missing attachment fails the call before anything is written. `atlassian_jira_get_issue`, `atlassian_jira_get_comments`, and `atlassian_jira_get_comment` read embedded files back the same way, so they survive a read, edit, and write; a file Jira cannot render stays a placeholder. Confluence refuses the syntax. For this, `atlassian_jira_get_comments` and `atlassian_jira_get_comment` gain a `richTextFormat` parameter and now return Markdown by default, like `atlassian_jira_get_issue`; pass `adf` for the ADF they returned before.
- `atlassian_confluence_delete_attachment` moves a Confluence attachment to the space's trash, from where a space administrator can restore it; it never deletes one permanently. Like page deletion, it is in the opt-in `confluence-admin` toolset.
- Every tool call is checked against the tool's parameters before it runs. A missing required argument, or an argument with a name the tool does not have (such as `content` instead of `body`), fails the call with a message that names the problem and lists the tool's parameters, instead of the generic "An error occurred invoking" or silently ignoring the argument.
- A `restrictions` parameter on `atlassian_confluence_create_page`, `atlassian_confluence_update_page`, and `atlassian_confluence_publish_page` sets who can view and edit the page: `open` (anyone who can see the space can view and edit it), `edit-restricted` (anyone can view it; only you can edit it), or `private` (only you can view and edit it). A page created as a private draft stays private when it is published, so pass `restrictions: open` to `atlassian_confluence_publish_page` to let the space see it. On `atlassian_confluence_create_page` it replaces `restrictToMe`, with the same defaults: private for a draft and open for a published page. On the other two tools it is optional, and leaving it out leaves the page's restrictions unchanged.
- `atlassian_confluence_discard_draft` discards the unpublished changes of a published page, by everyone, like the editor's Revert to last published version: the draft goes back to the published page, the page is no longer marked as having unpublished changes, and the published page and its versions do not change. Use it to drop a draft that `atlassian_confluence_update_page` or `atlassian_confluence_update_page_section` saved. The public REST APIs have no call for this (deleting a published page's draft is refused, and overwriting the draft leaves the page marked), so it uses the collaborative editing call that the editor makes. A page that was never published is refused.

- An `includeUnavailable` parameter on `atlassian_jira_get_transitions` also lists the transitions that a workflow condition hides in the issue's current state, such as one that requires a field to have a value. Each transition then has `isAvailable`, its `conditions` (what must be true for Jira to offer it, such as "Severity (customfield_10050) is not empty") and its `validators` (what is checked when it is applied), read from the workflow and described with field names. Reading the workflow can need administrator permission; without it, `rulesUnavailable` says why, and the transitions are still listed. It defaults to `false`, which lists only the available transitions, as before.
- Smart links in Markdown, for Confluence and Jira. An autolink, `<https://…>`, becomes a smart link (an `inlineCard`), which Confluence and Jira show with the current title of the linked page or issue, so the text follows a rename; `[text](URL)` is still a plain link. This works wherever Markdown is accepted, including `atlassian_confluence_update_page_section`, which could not add a smart link before.
- A `parentCommentId` parameter on `atlassian_jira_add_comment` replies to a comment, adding the new comment to its thread instead of starting a new one. Jira threads are one level deep and refuse a reply to a reply, so a reply's ID adds the new comment to the same thread, under the comment that started it. A comment that does not exist fails the call before anything is posted. Leaving it out starts a new thread, as before.
- `atlassian_confluence_get_trash` lists the pages and blog posts in a space's trash, with their count (0 when the trash is empty), and two tools in the opt-in `confluence-admin` toolset delete from it permanently: `atlassian_confluence_purge_page` deletes one page that is in the trash (any other page is refused, so it can't delete a page that wasn't deleted first), and `atlassian_confluence_empty_trash` deletes every page and blog post in a space's trash. A deleted item can't be restored.

### Changed

- Smart links in text are read back as `<URL>`, which converts back to the same smart link, instead of as `[URL](URL)`, which became a plain link when written back. They no longer count as content that Markdown cannot represent, so `atlassian_confluence_update_page` accepts a Markdown body for a page that has them; smart links shown as block cards or embeds still count. An `<https://…>` in Markdown, which stayed literal text before, now becomes a smart link.

### Fixed

- `atlassian_jira_transition_issue` adds its `comment` for every transition. It sent the comment in the transition request, which Jira applies only for a transition that has a screen; for one without, such as a move to To Do or Done in many workflows, Jira applied the transition, dropped the comment, and the tool reported success. The comment is now posted on its own after the transition, the result names the new comment's ID, and a comment that cannot be added fails the call with a message saying that the transition was applied. A mention or embedded file in the comment that cannot be resolved still fails the call before the issue moves.
- `atlassian_confluence_update_page` and `atlassian_confluence_update_page_section` keep the hidden `localId` of each heading, paragraph, table, row, cell, list, and list item that the new body still has. Confluence gave every node of a body written from Markdown a new ID, so comparing two versions of a page showed every node as changed in formatting, not only the ones that changed. Unchanged nodes keep their IDs, an edited node keeps the ID of the node it replaces so that the comparison shows its text change, and a new node gets an ID from Confluence.
- `atlassian_jira_transition_issue` explains why a transition that a workflow condition hides cannot be applied: it names the transition and the condition to meet, such as "It requires: Severity (customfield_10050) is not empty", instead of saying that the transition is not available and listing the others, which read as if it did not exist.
- `atlassian_confluence_move_page` with `append` refuses to move a page to the parent it already has, instead of reporting success. Confluence leaves such a page where it is, so reordering child pages that way appeared to work but did nothing; the error says to use `before` or `after` a sibling page.
